# LALIBAKERY: דף נחיתה

Next.js App Router, TypeScript, Tailwind 4, GSAP + ScrollTrigger, Lenis.

## הרצה

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # בדיקת build
npm test         # בדיקות הקוד (ההזמנה, קוד הכניסה, התזכורות, הטקסטים מה-CMS)
npm run test:db  # ההגירות של Supabase על Postgres אמיתי
```

## איפה מה

- **כל הטקסט, העוגות, המחירים, סוגי העוגות והתמונות:** ב-Studio של Sanity, בלי קוד, כולל עריכה בלחיצה על הטקסט באתר עצמו ("עריכה על האתר"). הקמה ואבטחה: `CMS.md`. ראו "גרסה 7" למטה.
- **הטקסט המובנה:** `content.ts`. מה שהאתר מציג כשה-CMS לא מחובר, ומה ש-`npm run seed` מעביר ל-Studio בפעם הראשונה. הקומפוננטות לא מייבאות אותו: הדפים מעבירים להן את הטקסטים.
- **טוקנים:** `app/globals.css`, בראש הקובץ.
- **תנועה:** `lib/gsap.ts` (eases, stagger, mask reveal משותף). Lenis מאותחל פעם אחת ב-`components/SmoothScroll.tsx`.
- **מעבר הרקע הגלובלי:** `components/BackgroundShift.tsx`.
- **Hero בתלת־ממד:** `components/hero3d/`. ראו "גרסה 4" למטה.
- **תמונות:** ראו `IMAGES.md`.
- **בונה העוגה, בלי המסך:** `lib/order/` (המודל, הסכמה ב-Zod, הבדיקה בשרת והשמירה בדפדפן). המסך עצמו: `components/CustomCakeWizard.tsx`.
- **ניטור, כניסה בטלפון ותזכורות:** ההקמה של כל השירותים ומשתני הסביבה ב-**`SERVICES.md`**. ראו "גרסה 6" למטה.
- **מועדון הלקוחות (בתכנון):** `supabase/`. ראו "הבא בתור" למטה.

## הבא בתור: מועדון לקוחות (Supabase)

- **`supabase/migrations/20260928090000_vip_club.sql`:** הסכמה המלאה, מוכנה ל-`supabase db push`: לקוחות לפי טלפון, הזמנות, חגיגות ותזכורות, תיעוד הסכמה (חוק הספאם), כרטיסייה וזיכוי בספרי תנועות, הפניות, והרשאות לכל שורה (RLS). רכישה נספרת כשבעלת העסק סוגרת את ההזמנה עם המחיר הסופי (`complete_order`), ושם, בפעולה אחת, נצברים ניקובים ומשולמים הזיכויים.
- **`supabase/migrations/20260929090000_cart_recovery.sql`:** טיוטות של בונה העוגה ללקוח מחובר, ההחלטה אם ומתי לשלוח תזכורת (`claim_cart_reminder`), שעות שליחה, והסכמה נפרדת לתזכורות. רץ אחרי הקובץ הקודם.

## גרסה 7: כל הטקסטים ב-Studio, ועריכה על האתר עצמו

כל מילה שמבקר רואה או שומע, בכל הדפים, נערכת עכשיו ב-Studio: כותרות, פסקאות, כפתורים, התפריט, הפוטר ושורת "פתוח עכשיו", תיאורי תמונות, טקסטים לקוראי מסך, הצהרת הנגישות ודף 404, הכותרת והתיאור לגוגל, כל מילה בבונה העוגה (כולל ההודעה שנשלחת בוואטסאפ, שמות הצבעים ובקשות ההסרה), והכיתוב על העוגה בתלת־ממד. שלושה מסמכים, אחד מכל סוג: **הגדרות כלליות**, **דף הבית** ו**דף הזמנת עוגה**, בראש התפריט של ה-Studio.

**עריכה על האתר (Presentation):** ב-Studio, "עריכה על האתר" מציגה את האתר האמיתי עם הטיוטות. לחיצה על טקסט כלשהו פותחת את השדה שלו בצד; מקלידים, והדף מתעדכן תוך רגע, בלי לאבד את מקום הגלילה, את מצב העוגה בתלת־ממד או עוגה שבאמצע הבנייה בבונה. Publish, והשינוי באתר. ההסבר המלא, ההקמה והאבטחה: "עריכה על האתר" ב-**`CMS.md`**.

- **באתר עצמו שום דבר לא השתנה:** ה-DOM של כל הדפים (המבנה, המחלקות, הטקסטים, הכיווניות, המטא-דאטה והנתונים לגוגל) זהה לזה של גרסה 6 (נבדק על ה-HTML שנבנה, דף אחר דף), והקוד של שכבת העריכה נטען רק במצב טיוטה. ה-First Load ירד: דף הבית 198KB ← 195KB, `/custom-cake` ‏211KB ← 207KB, כי הטקסטים עוברים עכשיו כנתונים לדף במקום כקוד בחבילה.
- **איך:** הדפים (`app/`) טוענים את הטקסטים בשרת (`sanity/content.ts`) ומעבירים אותם לקומפוננטות כ-props. מה שפורסם מונח על הטקסט המובנה של `content.ts` שדה אחר שדה, כך שאף פעם לא חסר טקסט: שדה ריק או ערך שהאתר לא יכול להשתמש בו מוחלף בטקסט המובנה (`lib/content/merge.ts`, הכללים ב-`sanity/rules.ts`). הדפים נשארים סטטיים (ISR) ומתרעננים ב-webhook, כמו הגלריה; מגרסה זו ה-webhook גם בונה אותם מחדש מיד, כך שהמבקר הראשון אחרי פרסום לא מחכה. כש-Sanity לא עונה, האתר ממשיך להציג את הגרסה האחרונה של הדף (לא את הטקסט המובנה) ומנסה שוב.
- **מצב טיוטה:** רק ה-Studio מפעיל אותו (`app/api/draft-mode/enable` בודק סוד חד־פעמי שה-Studio יוצר). אז הדף נבנה מהטיוטות, בלי מטמון, וכל טקסט נושא סימון בלתי נראה של המסמך והשדה שלו (stega). מה שאינו טקסט מוצג מנוקה מהסימונים: קישורי הטלפון, הוואטסאפ, המייל וה-Waze, השעות, ההודעה בוואטסאפ, הכיתוב בתלת־ממד והנתונים לגוגל (`lib/stega.ts`). השכבה עצמה: `components/cms/`.
- **הכיתוב בתלת־ממד:** האותיות מתעדכנות לבד כשהכיתוב משתנה, בלי לבנות מחדש את הסצנה (`components/hero3d/store.ts`). ה-Studio מקבל רק אותיות עבריות ורווחים, עד 12, כי אלה האותיות שיש לפונט של העוגה.
- **ה-Studio:** שלושת המסמכים מוגדרים ב-`studio/schemaTypes/site/spec.ts`: כותרת והסבר בעברית לכל שדה, לשוניות לפי סקשן, בדיקות (שדות חובה, שעות, טלפון, קישורים, מספר הפריטים בכל רשימה, הסוגריים המסולסלים שהאתר ממלא), ורשימות קבועות שאי אפשר להוסיף להן או למחוק מהן (חמשת השלבים של הבונה, שבעת ימי השבוע). אי אפשר ליצור, לשכפל או למחוק אותם. `npm run seed` ממלא אותם מ-`content.ts`.
- **נבדק:** `npm test` (101 בדיקות) כולל השוואה של כל שדה ב-Studio מול הטקסטים והכללים של האתר, והחזרה של כל הטקסטים המובנים דרך ה-Studio בלי שינוי. מול CMS מדומה: עריכות שפורסמו מגיעות לאתר, טיוטות לא; סוד שגוי נדחה; במצב טיוטה הטקסטים מסומנים, ואף קישור, שעה או נתון לגוגל לא; ו-CMS שנופל מיד אחרי פרסום לא מוריד את הדף של הבעלים.
- **חבילות:** `next-sanity` 11 (הגרסה האחרונה שתומכת ב-Next 15; 12 ומעלה דורשות Next 16), `@sanity/client`, `@vercel/stega`. `next-sanity` מתקין איתו גם את `sanity` (תלות חובה שלו), ולכן `node_modules` גדל, אבל שום דבר ממנו לא נכנס לחבילות של האתר. ה-Studio: `sanity/presentation`, שכבר חלק מ-Sanity 6.
- **לא ב-Studio, בכוונה:** התמונות של דף הבית, העיצוב, הודעות ה-SMS (קוד הכניסה והתזכורת: הנוסח שלהן מחויב בחוק הספאם), ודף השגיאה הכללי (`app/global-error.tsx`, שמוצג דווקא כשמשהו נכשל).

## גרסה 6: ניטור, הגנה על הכניסה, ועוגה שלא הולכת לאיבוד

שום דבר באתר לא נראה אחרת: אין שינוי בעיצוב, ב-DOM או בטקסטים. ההקמה של השירותים: **`SERVICES.md`**.

- **ניטור שגיאות (Sentry 11):** קריסות בדפדפן, בשרת וב-middleware, כולל קריסה של התלת־ממד ואובדן של הקשר הגרפי (עם רמת הביצועים של המכשיר). שגיאות בלבד: ה-First Load של דף הבית עולה מ-162KB ל-198KB. בלי כתובות IP, עוגיות וגוף בקשות, ומספרי טלפון מוסתרים לפני שהם יוצאים. פעיל רק כשמגדירים `NEXT_PUBLIC_SENTRY_DSN`. הקבצים: `lib/sentry.ts`, `instrumentation.ts`, `instrumentation-client.ts`, `sentry.server.config.ts`, `sentry.edge.config.ts`, `app/global-error.tsx`.
- **בונה העוגה נשמר בדפדפן:** לקוח שעוזב באמצע וחוזר (עד שבוע) מוצא את העוגה בשלב שבו עזב. נשמרת רק הטיוטה, אף פעם לא מספר טלפון, ונמחקת כשההזמנה נשלחת או כשמתחילים מחדש. מה שחוזר נבדק מול הקטלוג של היום (גודל או קרם שהוסרו נמחקים מהטיוטה, תאריך שעבר מתאפס). `lib/order/storage.ts`; ב-`/custom-cake` זה מוסיף 9KB (203KB ← 212KB).
- **בדיקת ההזמנה בשרת (Zod):** `lib/order/validate.ts` בודק כל הזמנה מול הקטלוג החי: מזהים שקיימים ושייכים יחד, צבעים מהפלטה, התנגשויות אלרגנים, תאריך שלא עבר, טקסט נקי (בלי תווים נסתרים או תווי כיווניות) ובאורך מוגבל. המחיר והסיכום נבנים מחדש בשרת: מה שהדפדפן שלח לא נקרא. יחובר כשההזמנה תישלח לשרת.
- **הגנה על קוד הכניסה ב-SMS:** `app/api/hooks/send-sms` (ה-hook של Supabase): רק ניידים ישראליים, 3 קודים ב-15 דקות ו-6 ביום לכל מספר, 150 ביום לכל האתר, והתראה ב-80%. `middleware.ts` מגביל בקשות כתיבה לפי כתובת. השליחה דרך Twilio (`lib/sms.ts`); ספק ישראלי הוא פונקציה אחת נוספת.
- **תזכורת "שכחתם את העוגה?":** צד השרת: `lib/cart/`, `app/api/cart/remind` וההגירה החדשה. תזכורת אחת, רק למי שהסכים, לא בלילה ולא בשבת, ומתבטלת מעצמה כשההזמנה נשלחת.
- **`CustomCakeWizard.tsx`:** הלוגיקה (הקטלוג, המחיר, הסיכום) עברה ל-`lib/order/model.ts`, בלי שינוי, כדי שהשרת ישתמש באותו קוד. נוספו רק השמירה והשחזור. ה-DOM, המחלקות והעיצוב לא השתנו; לקישור לוואטסאפ נוסף רק `onClick` שמוחק את הטיוטה השמורה.

## גרסה 5: ניהול תוכן (Sanity)

הבעלים מעדכנת בעצמה את העוגות בגלריה (שם, תיאור, מחיר, סוג, תמונה, סדר) ואת הקטלוג של בונה העוגה (סוגים, גדלים, מחירים, טעמים, קרמים ואלרגנים), מהטלפון או מהמחשב. הבונה עצמו בדף משלו: **`/custom-cake`** (`app/custom-cake/page.tsx`). ה-Studio הוא אפליקציה נפרדת ב-`studio/`, מתארח אצל Sanity ונעול בהתחברות. האתר רק קורא ממנו, בשרת: הדף נשאר סטטי, ומתרענן כשמשהו מתפרסם (webhook חתום) או לכל המאוחר אחרי שעה. התמונות מוגשות מה-CDN של Sanity, בגדלים ובפורמטים שהדפדפן צריך.

בלי `NEXT_PUBLIC_SANITY_PROJECT_ID` האתר מציג את התוכן המובנה שלו, בדיוק כמו קודם. כל ההקמה, משתני הסביבה ומודל האבטחה: **`CMS.md`**.

**מסלול הזמנה אחד:** כל הדרכים בדף הבית מובילות לבונה העוגה ב-`/custom-cake`: הכפתור ב-hero ("תכננו ושלחו בוואטסאפ"), "הזמנה" בכותרת, כפתורי האירועים ב"מה שניסיתם", הכפתור "לתכנון העוגה" מתחת לצעדים ב"איך מתחילים" והכפתור בסגירה. מתכנן ההזמנה הישן הוסר מ"איך מתחילים", יחד עם הקוד, הטקסטים (`start.builder`) והעיצוב שלו; במקומו, מתחת לשלושת הצעדים, כפתור בסגנון של כפתורי האירועים. וואטסאפ ישיר נשאר כערוץ יצירת קשר: הכפתור הצף, "שאלו בוואטסאפ" בשאלות, והפוטר.

## גרסה 4: Hero בתלת־ממד

במקום תמונת הרקע: עוגה אחת שמרכיבה את עצמה לפי הגלילה ("האנטומיה של עוגה"), ומסביבה הממתקים של גרסה 7 (מקרונים, שוקולדים, פניני זהב, תותים). הטקסט, הכפתורים, הצבעים והניתוב לא השתנו.

- **הגלילה מובילה:** שום דבר לא מתנגן לבד. ScrollTrigger ב-`Hero.tsx` מזיז את `hero3d.progress` מ-0 ל-1 (scrub), ובזמן הזה הבמה (`.hero-stage`) נעוצה ב-sticky, כמו במנגנון, ולכן זה עובד גם במובייל.
- **השלבים:** שכבות הספוג והקרם נוחתות, קרם עוטף, זילוף שוליים, סרט וקשת זהב, הכיתוב "מזל טוב", עלי זהב ופרחים, ובסוף פרוסה נשלפת. החלון של כל שלב בגלילה: `components/hero3d/timeline.ts`. תנועות המצלמה: `framing.ts`.
- **אורך ההרכבה:** `--hero-assembly` ב-`globals.css` (ברירת מחדל `240svh`, בנוסף למסך עצמו).
- **הכיתוב על העוגה:** ב-Studio, דף הבית, פתיחה (מגרסה 7). `INSCRIPTION` ב-`components/hero3d/config.ts` הוא ברירת המחדל (אותיות עבריות ורווחים; הפונט כולל את כל הא"ב).
- **צבעי הסטודיו:** `BACKDROP` ב-`config.ts`. הרקע שמוצג עד שהסצנה עולה (בלוק "HERO 3D" ב-`globals.css`) מצויר באותם צבעים, כדי שהעוגה תיכנס בלי שהרקע יזוז: משנים את שניהם יחד.
- **ביצועים:** שלוש רמות (`TIERS` ב-`config.ts`) לפי המכשיר. טלפונים: בלי אפקטים ובלי מפות צל. דסקטופ: עומק שדה, bloom וצללים רכים. מחשבים חזקים: גם ambient occlusion ו-HDRI ברזולוציה מלאה. קוד התלת־ממד (כ-265KB ב-gzip) נטען בחבילה נפרדת, ורק בדפדפן שיכול להריץ אותו; ה-First Load של הדף: 163KB (מגרסה 6, עם Sentry: 198KB). כשה-hero לא על המסך, הקנבס לא מצייר.
- **חלקות:** לפני שהסצנה מופיעה היא מתחממת מחוץ למסך: כל ה-shaders מתקמפלים וכל ההרכבה מתורגלת פעם אחת, גם כשחוזרים לדף (למשל מ-`/custom-cake`). כשה-hero יוצא מהמסך וחוזר, או כשהרזולוציה משתנה, הסצנה עצמה לא מתרנדרת מחדש. התנועה מחושבת לפי שעון הפריימים של הדפדפן (`clock.ts`), והקוד שרץ בכל פריים לא מקצה זיכרון. הרזולוציה יורדת רק במכשיר שלא מחזיק 40 פריימים בשנייה, ורק כשהדף במנוחה, אף פעם לא באמצע גלילה. כל סוג ממתק הוא InstancedMesh אחד (קריאת ציור אחת לכל סוג).
- **גיבוי:** בלי JS, בלי WebGL 2, אם הקבצים לא נטענו או אם הגרפיקה קורסת לצמיתות, ה-hero חוזר להיות בדיוק מה שהיה: התמונה, ובדסקטופ הכרטיס הנעוץ.
- **פחות תנועה:** מי שביקש (`prefers-reduced-motion`) רואה את העוגה השלמה, בלי הרכבה, וה-hero בגובה מסך אחד.

| קובץ | מה |
|---|---|
| `components/hero3d/HeroCanvas.tsx` | נקודת הכניסה (קלה, בחבילה הראשית): בודק WebGL 2, מודד איפה יש לעוגה מקום ליד הטקסט, טוען את הסצנה, ומחזיר את התמונה כשצריך |
| `HeroScene.tsx` | ה-`<Canvas>`: תאורה, HDRI, רמות ביצועים, החימום מחוץ למסך, הרזולוציה, והתאוששות כשהקשר הגרפי אובד |
| `CakeAssembly.tsx`, `cakeParts.ts`, `Letters.tsx` | העוגה, השלבים והכיתוב |
| `FloatingSweets.tsx`, `SparkleTrail.tsx` | הממתקים של גרסה 7 ושובל האור |
| `CameraRig.tsx`, `framing.ts` | המצלמה, והמסגור באזור הפנוי מהטקסט |
| `Backdrop.tsx`, `Effects.tsx`, `materials.ts` | רקע הסטודיו, האפקטים והחומרים |
| `timeline.ts`, `config.ts`, `store.ts`, `clock.ts` | ציר הזמן, ההגדרות, המצב המשותף לדף ולסצנה, והשעון של הסצנה |
| `public/3d/` | טקסטורות, HDRI ופונט הכיתוב |
| `scripts/hero3d-textures.py` | מייצר מחדש את הטקסטורות (Python 3 עם numpy, scipy ו-Pillow) |

**שינויים בקבצים הקיימים:** `components/sections/Hero.tsx` (עטיפת `.hero-stage`, הקנבס בתוך `.hero-media` מתחת ל-scrim, ה-`pin` הוסר מה-clip-path כי ה-sticky מחליף אותו, ו-ScrollTrigger שמזיז את ההרכבה; הטקסט, הכפתורים והמחלקות לא השתנו), `app/globals.css` (בלוק "HERO 3D" חדש מתחת לבלוק ה-HERO), ו-`components/MaskLines.tsx` (טיפוס בלבד: `as` מקבל רשימת תגיות, כי הטיפוסים של React Three Fiber שברו את `ElementType`).

**רישיונות:** פונט הכיתוב הוא Noto Serif Hebrew Bold (SIL Open Font License), מומר לפורמט של three.js. ה-HDRI הוא studio_small_03 של Poly Haven (CC0). הטקסטורות נוצרו בסקריפט, בלי צילומים.

**לבדיקות:** ווים שלא עושים כלום אם לא מגדירים אותם לפני טעינת הדף: `window.__heroQuality = "low" | "medium" | "high"` (כופה רמה), `window.__heroProgress = 0.5` (עוצר על רגע בהרכבה), `window.__heroSnap = true` (מצלמה בלי החלקה). `window.__heroStats` מציג פעמיים בשנייה draw calls, משולשים, shaders והאזור שנמדד.

**הערה:** `npm audit` מדווח על 2 פגיעויות ב-postcss שמגיע בתוך Next 15. הן בזמן build בלבד, והתיקון דורש מעבר ל-Next 16.

## גרסה 3: לוגו, צבעים, פוטר, וכל מה שאתר צריך

- **לוגו חדש בווקטור:** `public/brand/logo.svg`, שרטוט מחדש של הלוגו המקורי. הטקסט הומר לצורות, כך שהלוגו חד בכל גודל ולא תלוי בפונט. יש גם `logo-1024.png` ו-`logo-512.png` לאינסטגרם, לוואטסאפ ולמדבקות. אייקון לדפדפן: `app/icon.svg`, ולאייפון: `app/apple-icon.png`.
- **פלטה חמה:** שוקולד במקום שחור, ווניל במקום לבן, קרמל-זהב לכפתורים, והוורוד של הלוגו כצבע מותג (פס ההזמנה, פס האירועים והפוטר).
- **כותרת נצמדת:** מופיעה אחרי ה-hero כשגוללים למעלה, עם ניווט, "הזמנה" וחיוג.
- **פוטר:** שולי זילוף בשוקולד, לוגו גדול, שעות פעילות עם "פתוח עכשיו / סגור עכשיו" לפי שעון ישראל, טלפון, וואטסאפ, מייל ורשתות חברתיות. כתובת וניווט ב-Waze מופיעים ברגע שממלאים `business.address`.
- **לגוגל:** נתונים מובנים (Bakery: שם, טלפון, שעות), `robots.txt`, `sitemap.xml`.
- **דפים:** הצהרת נגישות (`/accessibility`) ודף 404.
- **נגישות:** קישור "דלג לתוכן", והכותרת הנצמדת לא נגישה במקלדת כשהיא מוסתרת.

## גרסה 2: מילוי החללים ומשיכת לקוחות

- **הכאב:** תמונת עוגה בקופסה לצד הפסקה. מתחילה באפור ומקבלת צבע יחד עם המילים.
- **מה שניסיתם:** אחרי המשפט המסכם מופיעה השאלה עצמה ("מה האירוע שלכם?") עם כפתורי אירועים. (מגרסה 5: כל כפתור פותח את דף ההזמנה.)

- **איך מתחילים:** מתכנן הזמנה לצד שלושת הצעדים. (הוסר בגרסה 5: בונה העוגה בדף `/custom-cake` מחליף אותו.)

- **סגירה:** תמונה לצד הכותרת.
- **כפתור וואטסאפ צף:** עכשיו גם בדסקטופ. נעלם ליד ה-hero, הכפתור של "איך מתחילים", הסגירה וכרטיס יצירת הקשר.

## חריגות מודעות מהמפרט

- **פונטים ב-`<link>` ולא `next/font`:** סביבת הבנייה חסמה את Google Fonts. בפרויקט אמיתי אפשר לעבור ל-`next/font/google`.
- **מעבר הרקע מזיז משתני CSS** (`--bg`, `--fg`, `--fg-soft`) ולא את `body` ישירות, כדי שגם טקסט משני וקווים דקים יתהפכו יחד.
- **המחיקה בסקשן 3 היא `background-size` ולא `scaleX`:** כשהשורה נשברת לשתיים במובייל, `scaleX` מחק רק חלק. עכשיו כל שורה נמחקת, עדיין מימין לשמאל.
- **כרטיסי המנגנון מתעמעמים בשכבה אטומה** ולא ב-`opacity` על הכרטיס. `opacity` הפך אותם לשקופים וחשף את הכרטיס שמתחת.
- **הדגשת המילים משתמשת ב-`scrub: 1`** ולא `true`, לפי הכלל הגלובלי במפרט.
- **Hero:** תמונה 16:10 לדסקטופ ו-4:5 למובייל, כי המדיה ממלאת את כל המסך. מגרסה 4 התמונה היא הגיבוי של התלת־ממד.
- **Hero, גרסה 4:** ה-`pin` של ה-hero הוחלף ב-sticky וה-hero גבוה יותר (`--hero-assembly`), כדי שלעוגה יהיה זמן להיבנות גם במובייל. בלי תלת־ממד הוא חוזר לאורך של ה-pin המקורי.
